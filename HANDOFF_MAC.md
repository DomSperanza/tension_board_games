# Handoff: build and test the iOS app on a Mac

You are picking up **Tension Board Games**, a web + Capacitor app that turns a Tension Board's LEDs into arcade games over Bluetooth. The work so far happened on Linux, where iOS can't be built. Your job is to get the iOS app running on the owner's iPhone, test it against a real board, and fix what breaks. Work through the steps in order and tick the checklists as you go.

## Current state (as of 2026-10-27, v0.2.0)

| Part | State |
| --- | --- |
| Web app (`src/`) | Works in desktop Chrome. Not yet tried against a real board. |
| Games | Gap Drop and Reach (ported from [emre9690/kilter_board_game](https://github.com/emre9690/kilter_board_game)), plus Barrage and Serpent (new, each with an optional co-op mode). All speed up to a top speed at level 5. 111 unit tests pass. |
| Boards | All 10 Tension sizes (5 × TB1, 5 × TB2), extracted from the Tension app database. |
| Android (`android/`) | Debug APK builds. In the emulator the app launches, asks for the Nearby Devices permission, scans for Aurora boards, cancels cleanly, and runs games with the screen kept awake. **Never connected to a real board.** |
| iOS (`ios/`) | Project generated with `npx cap add ios` (Swift Package Manager, no CocoaPods), and `NSBluetoothAlwaysUsageDescription` is set in `ios/App/App/Info.plist`. **Never built.** |

## How it fits together (read before changing code)

- **No bundler, no build step for the web code.** `src/` is plain ES modules served as-is. Capacitor's `webDir` is `src`.
- **Two Bluetooth transports behind one class**, in `src/js/ble.js`:
  - `webTransport`: Web Bluetooth, used in browsers.
  - `nativeTransport`: the `@capacitor-community/bluetooth-le` plugin, used inside the iOS/Android app. `defaultTransport()` picks it when `window.Capacitor.isNativePlatform()` is true.
  - `AuroraConnection` holds the link, keeps only the newest frame while a write is in flight, and splits messages into 20-byte chunks.
- **Plugin loading:** because there's no bundler, `src/js/native.js` injects the plugins' prebuilt browser bundles from `src/vendor/` at runtime, and only inside the app. `src/vendor/` is **gitignored** and is filled by `npm run cap:sync` (via `scripts/vendor-capacitor.mjs`). If Connect fails with "Could not load vendor/…", you skipped that step.
- **Screen kept on:** `@capacitor-community/keep-awake` in the app; the Screen Wake Lock API in browsers (`holdWake` in `src/js/app.js`).
- **LED protocol:** `src/js/protocol.js` (Aurora API v2 and v3). The API level comes from the board's Bluetooth name: names ending `@3` mean v3, anything else means v2. Settings → Protocol overrides it.
- **Game rules** are pure functions with no DOM or timers: `src/js/game.js` (Gap Drop), `reach.js`, `barrage.js`, `serpent.js`, with the shared speed-up in `ramp.js`. `src/js/app.js` runs the timeline, the UI and the co-op controller pad (each game's `coop.controls` in `GAMES`).
- **Board data:** `src/js/boards-data.js` is generated by `scripts/extract-boards.py`. Don't edit it by hand.

## 1. Set up the Mac

- [ ] Xcode, current version, opened once so it installs its components.
- [ ] Node 22. The repo has `.nvmrc`: `nvm install && nvm use`. Capacitor 8 requires Node ≥ 22.
- [ ] Clone and install:
  ```bash
  git clone https://github.com/DomSperanza/tension_board_games.git
  cd tension_board_games
  npm install
  npm test            # expect 111 passing
  npm run cap:sync    # fills src/vendor and copies web assets into ios/ and android/
  ```

## 2. Build onto the iPhone

- [ ] `npx cap open ios` opens `ios/App/App.xcodeproj` in Xcode.
- [ ] Target **App** → Signing & Capabilities: tick "Automatically manage signing" and choose the owner's Apple ID team (Xcode → Settings → Accounts to add one).
- [ ] If Xcode says the bundle ID `com.tensionboardgames.app` isn't available, change it to something unique such as `com.<owner>.tensionboardgames`. Change `appId` in `capacitor.config.json` to match, then run `npm run cap:sync` again.
- [ ] Plug in the iPhone, pick it as the run destination and press Run. On the phone you may need to turn on Developer Mode (Settings → Privacy & Security), and trust the developer certificate (Settings → General → VPN & Device Management).
- [ ] Set the version: Target **App** → General → Version to match `version` in `package.json` (Android reads it automatically; iOS doesn't yet).
- [ ] With a free Apple ID the install expires after 7 days; run again from Xcode to renew it. TestFlight or the App Store needs the paid Apple Developer Program.

After any change in `src/`, run `npm run cap:sync` before building again. Xcode doesn't watch `src/`.

## 3. Test against the real board

Close the official Tension app first: the board accepts only one Bluetooth connection at a time. Pick the right board size in the dropdown, because each size numbers its LEDs differently.

- [ ] App launches with the dark UI and no "No Bluetooth in this browser" warning.
- [ ] Connect → iOS shows the Bluetooth permission prompt (once) → a picker lists the board.
- [ ] After choosing the board the status shows its name with a green dot.
- [ ] **Clear lights** works, and **Disconnect** turns the board off.
- [ ] Gap Drop: red bars fall down the real wall, and the gaps line up with the on-screen preview.
- [ ] Reach: one cluster lights, then green → yellow → red → jumps.
- [ ] Barrage solo: purple aliens march along the top; red bolts fall; Speed climbs to 5 and stays.
- [ ] Barrage co-op (tick Co-op): the ◀ Fire ▶ pad works during play; the blue cannon moves on the bottom row; shots stop bolts and kill aliens; a cleared wave brings a new one.
- [ ] Serpent solo: green snake with a bright head chases orange apples and grows.
- [ ] Serpent co-op: the ▲◀▼▶ pad steers it; it turns away from walls instead of crashing.
- [ ] The pad buttons respond instantly on touch (they use pointerdown) and don't zoom the page on double tap.
- [ ] The countdown (3, 2, 1, GO) and the final score are readable on the wall.
- [ ] The screen stays on for a whole game with the phone lying flat.
- [ ] Locking the phone or leaving the app mid-game, then coming back: no crash. Reconnect works if the link dropped.
- [ ] Repeat a quick check on the web version in Bluefy (iPhone) or Chrome (Android) if hosting is set up.

## 4. Known risks: check these first if something's wrong

1. **Wrong colors or garbled lights (protocol level).** iOS can report a cached Bluetooth name for the board that lacks the `@3` suffix, so the app falls back to v2. Try Settings → Protocol → v3. If that fixes it, consider reading the advertised local name instead. The plugin's `requestDevice` returns only the `BleDevice` name; `requestLEScan` results include `localName`.
2. **The board doesn't show up in the picker.** The scan filters on the Aurora advertised service `4488b571-7806-4df6-bcff-a2897e4953ff`. Turn on Settings → Show all devices to see everything nearby, then work out what the board actually advertises.
3. **Writes fail or lights lag.** `nativeTransport.connect` chooses write-with-response vs without from the characteristic's properties. Frames are chunked to 20 bytes. If the link is slow, check whether write-without-response is available and faster.
4. **The phone sleeps mid-game.** Check that the keep-awake plugin is in the iOS Package.swift (`npx cap sync ios` lists the plugins it found).

## 5. Rules for changing the code

- Run `npm test` after every change and keep the game logic pure (no DOM, timers or Bluetooth in `game.js`, `reach.js`, `barrage.js`, `serpent.js` or `ramp.js`).
- Keep both transports working. Anything platform-specific goes behind the transport in `ble.js` or in `native.js`.
- Don't commit `src/vendor/`, build outputs, or the Tension database (`*.db`).
- Match the existing style: small modules, short comments that explain *why*.
- Commit in small steps with clear messages and push to `main` (or a branch, if the owner prefers).
